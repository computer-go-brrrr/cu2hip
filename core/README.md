# core/ — extracted verified core + JSON driver (G4)

## Layout

- `lib/extracted/` — Rocq extraction output (`Map.map_program` + deps).
  Regenerated by `make -C ../rocq`; never hand-edit (see `rocq/Extract.v`).
- `lib/mini_json.ml` — Yojson `<->` extracted AST (`cu2hip_core` library).
- `bin/minimap.ml` — `minimap <in.minicuda.json> -o <out.minihip.json>`.

## Value transport bounds (trusted shell, documented)

- `Z` extracts to OCaml `int` (63-bit). The driver only TRANSPORTS
  literals (never computes); the frontend emits 32-bit-range literals,
  so this is exact on all reachable inputs.
- `PrimFloat.float` extracts to binary64 via `rocq-runtime.kernel/Float64`
  (`of_float`/`to_float` at the JSON boundary); exact for all JSON doubles.
- Rocq `string` extracts to OCaml `char list` (converted at the boundary).

The proof (`Sim.vo`) is about the Gallina model; extraction fidelity for
these transports is TCB (Rocq extractor + OCaml compiler), same class as
CompCert's extraction trust.

eval $(opam env --switch=cuda-rocm-rocq)

`tests/fixtures/*.minihip.json` exactly (checked in `tests/run_e2e.sh`).
